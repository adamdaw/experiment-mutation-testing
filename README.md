# Mutation-testing experiment

## Question

This experiment asks two questions:

1. Does 100% line, branch, and function coverage mean the tests would catch a wrong implementation?
2. How much does changing only the mutation-operator set move the reported mutation score?

## Method

Three deliberately small JavaScript fixtures each have 100% line, branch, and function coverage. The same nine tests are run unchanged against mutations generated by Stryker: first with its full operator set, then with only `EqualityOperator` enabled. Coverage analysis is disabled, so every test runs for every mutant.

The tool versions are pinned by `package.json` and `package-lock.json`:

- Node.js 24.21.0
- Stryker 10.0.0 (`@stryker-mutator/core`)

The results were reproduced on 2026-10-07. Raw Stryker JSON is committed as `results/full.json` and `results/reduced.json`; its source-file paths are repository-relative.

## Reproduce

From a fresh clone with Node 24.21.0:

```sh
npm ci
npm test
npm run coverage
npx stryker run
npx stryker run stryker.reduced.conf.json
```

The two Stryker commands regenerate the committed JSON result files.

## Results

All nine tests pass. Every source file reports 100% line, branch, and function coverage.

| Full operator set | Mutants | Killed | Survived | Score |
| --- | ---: | ---: | ---: | ---: |
| `src/alerts.js` | 10 | 0 | 10 | 0.00% |
| `src/dates.js` | 11 | 9 | 2 | 81.82% |
| `src/discount.js` | 9 | 6 | 3 | 66.67% |
| **Total** | **30** | **15** | **15** | **50.00%** |

| EqualityOperator only | Mutants | Killed | Survived | Score |
| --- | ---: | ---: | ---: | ---: |
| `src/alerts.js` | 1 | 0 | 1 | 0.00% |
| `src/dates.js` | 4 | 2 | 2 | 50.00% |
| `src/discount.js` | 2 | 1 | 1 | 50.00% |
| **Total** | **7** | **3** | **4** | **42.86%** |

The two surviving `dates.js` mutants are the same in both runs. Only the denominator changes: the full run kills 9 of 11 mutants, while the reduced run kills 2 of 4.

The experiment therefore gives a concrete counterexample to treating complete coverage as proof that tests detect incorrect behavior. It also shows that changing only the operator set changes the reported score, from 50.00% to 42.86% overall and from 81.82% to 50.00% for `dates.js`.

## Limitations

These are tiny, authored fixtures designed to make specific testing failures visible. The measurements describe only these fixtures with the pinned versions; they are not a general mutation-survival rate, a benchmark of real-world projects, or evidence that one operator set is universally preferable. Some surviving mutants can also be behaviorally equivalent for the exercised domain, so a survivor is a prompt for inspection rather than automatically a defect.

For the broader argument and context, see [Mutation Testing: Who Tests the Tests?](https://adamdaw.com/writing/mutation-testing-who-tests-the-tests/).
